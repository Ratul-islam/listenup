# ListenUp — Android app

Expo (SDK 57) + Expo Router, styled with [Uniwind](https://docs.uniwind.dev) (Tailwind v4) and [HeroUI Native](https://heroui.com/docs/native). Talks to the Fastify API in `../backend`.

## Setup

```bash
pnpm install
cp .env.example .env   # then fill it in
```

| Variable | Value |
|---|---|
| `EXPO_PUBLIC_API_URL` | API base including `/api/v1`. Phone over USB: `http://localhost:8000/api/v1` + `adb reverse tcp:8000 tcp:8000`. Emulator: `http://10.0.2.2:8000/api/v1`. |
| `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID` | The **Web** OAuth client ID (same as the backend's `GOOGLE_CLIENT_ID`). Empty hides Google sign-in. |
| `EXPO_PUBLIC_REVENUECAT_GOOGLE_KEY` | RevenueCat's public Google Play API key. Empty keeps plans as "Available soon". |

Google sign-in also needs an **Android** OAuth client in the same Google Cloud project, registered with package `dev.ratul.tts` and your debug keystore's SHA-1 (`cd android && ./gradlew signingReport`). The app never uses that ID directly, but Google rejects sign-in without it.

## Run

Native modules (Google Sign-In, SecureStore, embedded fonts) mean this runs in a **development build**, not Expo Go.

```bash
pnpm android     # build + install the dev client (first time, or after native changes)
pnpm start       # Metro for an already-installed dev client
pnpm typecheck && pnpm lint
```

`android/` is generated by `expo prebuild` and git-ignored; configure native behaviour in `app.json`.

## Structure

```
src/
  app/                       routes only (thin re-exports of feature screens)
    _layout.tsx              providers, splash, auth gate (Stack.Protected)
    (auth)/                  onboarding (3 steps), sign-in, sign-up, verify-email, password reset
    (app)/(tabs)/            Soundshelf, Explore, Studio + floating tab bar and mini player
    (app)/player.tsx         full-screen player
    (app)/import.tsx         import a file, photo, link or pasted text
  features/<feature>/        api/ hooks/ components/ screens/ store/ lib/
    library/                 documents list, cards, import
    player/                  audio engine (expo-audio), player store, synced text, controls
    voices/                  voice list, previews, preferences
  components/ui/             design-system primitives (cloud background, glass card, pills, buttons…)
  lib/                       api client, query client, secure storage, haptics, theme tokens
  global.css                 ListenUp theme tokens (light/dark) and HeroUI overrides
```

## Playback model

- Documents are split on the server into short chunks of one language. The player streams them one by one with a single expo-audio player and preloads the next chunk while the current one plays.
- The server generates speech the first time a chunk is requested and caches it, so replays are free.
- "Live Synchronized Text" highlights the exact sentence; the word position inside it is estimated from timing because speech providers don't return word timestamps.
- Progress and listening time are saved every 15 s and on pause; they drive resume, the stats card and the streak.

## Auth model

- Access token lives in memory; the refresh token and cached profile live in SecureStore.
- `lib/api/client.ts` attaches the access token to `auth: true` requests and, on a 401, refreshes once and retries.
- Refreshes are single-flight (`refreshAccessToken` in `features/auth/store/auth.store.ts`): the backend treats a refresh token used twice as stolen and revokes the session, so concurrent requests must share one refresh.
- Being offline at launch keeps you signed in with the cached profile; only an explicit 401 from the server signs you out.

## Design

Built from the PNGs in `../design` (ListenUp "Cloudspun" onboarding, "Soundshelf" library, audio player): lavender cloud gradients, white glass cards, an indigo primary and a violet→pink voice accent in the player. Type is Plus Jakarta Sans with JetBrains Mono for times, both embedded natively via the `expo-font` plugin so real weights render on Android. Light and dark follow the system.
